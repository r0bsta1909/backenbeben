LAN DISCOVERY / FINAL BUILD — 2026-10-26

Implementation
LAN_SPIELEN.bat + server/lan_play.py discover existing hosts using the versioned
UDP request/reply protocol on 8766. One host opens directly, multiple hosts are
listed; no host is created without choosing H. Host continues serving HTTP/WS
on 0.0.0.0:8765. Broadcast addresses come from actual IPv4 interface prefixes.
Responses require the request nonce and a local IPv4 source; navigation uses the
packet source address and validated port, never a supplied arbitrary URL.
Malformed/public requests are ignored; replies are rate limited per source.
Windows UDP connection-reset responses are handled during an empty search.

The browser receives a public roster and joinable tournament list, updated at
most once per second when changed. Profiles use the existing character validator.
Public snapshots exclude private resume credentials and disconnected players.
Active event identity cannot be changed through presence. Full/running events
are omitted from joinable results; the server remains authoritative on entry.
LAN modal supports direct tournament joins, automatic duel pairing, reconnect
state, visible rejected-join notices, Escape and narrow screens.

Firewall setup resolves the actual base Python executable behind the Windows
venv launcher. TCP 8765 + UDP 8766 are limited to LocalSubnet and that executable.
Default setup covers Private only; IncludePublic is an explicit opt-in. The user
explicitly approved that extension on 2026-10-20. All four enabled rules, ports,
profiles, application path and LocalSubnet filters were inspected after setup.
No global Windows network-category change was made.
